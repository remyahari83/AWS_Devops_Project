In the development env/visual studio code:

1. Build a new image:
docker build -t qa-evaluator-app .

2. make sure it works fine.
docker run -p 8000:8000 --env-file .env qa-evaluator-app

http://localhost:8000

3. Tag with a new version.
docker tag qa-evaluator-app:latest 521765619271.dkr.ecr.us-east-1.amazonaws.com/qa-evaluator-app:1.0.0

4. Push

Before that create ecr repository in aws:
aws ecr create-repository --repository-name qa-evaluator-app --region us-east-1

aws ecr get-login-password --region us-east-1 | docker login --username AWS --password-stdin 521765619271.dkr.ecr.us-east-1.amazonaws.com

docker push 521765619271.dkr.ecr.us-east-1.amazonaws.com/qa-evaluator-app:1.0.0

5. Do the code change:
docker build -t qa-evaluator-app:1.1.0 .

6. Test again.

docker run -p 8000:8000 --env-file .env qa-evaluator-app:1.1.0

7. Tag again.

docker tag qa-evaluator-app:1.1.0 521765619271.dkr.ecr.us-east-1.amazonaws.com/qa-evaluator-app:1.1.0

8. Push
docker push 521765619271.dkr.ecr.us-east-1.amazonaws.com/qa-evaluator-app:1.1.0

Blue:
521765619271.dkr.ecr.us-east-1.amazonaws.com/qa-evaluator-app:1.0.0

Green:
521765619271.dkr.ecr.us-east-1.amazonaws.com/qa-evaluator-app:1.1.0


9. Put rollout.yaml, service-active.yaml, service-preview.yaml in gitlab gitops directory. 

-------------------------------------------------------------------------------------------

1. Apply the Rollouts manifest server-side

Run:
kubectl create namespace argo-rollouts

cd /tmp

curl -L https://github.com/argoproj/argo-rollouts/releases/latest/download/install.yaml \
  -o argo-rollouts-install.yaml

Then:

kubectl apply --server-side --force-conflicts \
  -f /tmp/argo-rollouts-install.yaml

Server-side apply avoids the huge last-applied-configuration annotation that is causing the error.

2. Check the CRDs

Run:

kubectl get crd | grep argoproj.io

You should see at least:

analysistemplates.argoproj.io
analysisruns.argoproj.io
clusteranalysistemplates.argoproj.io
experiments.argoproj.io
rollouts.argoproj.io
3. Check the controller
kubectl get pods -n argo-rollouts

Login to argocd and create repository connection and application. give the path of yaml files (3 - rollout, service-active, service-preview) and url of GitLab.

Sync it. then check the loadbalancer address of the application.
kubectl get rollouts -n qa
kubectl get pods -n qa -o wide
kubectl get svc -n qa
kubectl get rs -n qa

Then access the url. should be able to see that application is blue version.
